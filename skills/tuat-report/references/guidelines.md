# TUAT レポート 規約（構成・体裁・引用）

東京農工大の演習・実験レポートの構成・体裁・引用の目安。学科配布の「レポートの書き方」を手元にあれば必ず読み、そちらと課題PDFの指定を優先する。科目固有の指定（課題PDF／科目メモ）があればそちらを優先し、差異はレポート内に明記する。

## レポート構成（チェックリスト）

見出し番号は 要旨・参考文献 に付けない。見出しは3段階（章/節/項）まで、それ以降は箇条書き (1)/(A)/(a)。プログラム/実験ごとに本文ブロックを繰り返す。

- [ ] **要旨**（番号なし。おわりにを簡潔にまとめたもの。任意）
- [ ] **1. はじめに**（背景・目的・何を明らかに/改善するか・本文構成。最後に構成を一言）
- [ ] **概要**（何のプログラム/実験/検証かを簡潔に）
- [ ] **設計**（機能・理論・アルゴリズム・設計方針・前提・必要ならフローチャート）
- [ ] **実現/実装**（主要関数の抜粋＋関数・変数・設計との対応。長い全文は付録/提出物へ）
- [ ] **実験環境**（規模/行数・計算機・OS・言語/コンパイラ/ツール・ライブラリ・実行条件）
- [ ] **実験手法**（再現できるよう手順を具体的に）
- [ ] **実験結果**（事実のみ。図表・数値・要約ログ。考察はここに書かない）
- [ ] **考察**（エビデンスに基づく議論。結果の数値を引用。予測との比較・原因・妥当性）
- [ ] **おわりに**（まとめ・目的の達成度・結論）
- [ ] **謝辞**（協力者がいれば）
- [ ] **参考文献**（番号なし見出し。番号付き [1] で本文から参照）
- [ ] **付録**（長いソース・大きな結果。複数なら付録1,2…。本文から必ず参照）

## 体裁規則

- だ・である調で統一。話し言葉（「ちょっと」「とか」）は書き言葉（「少し」「など」）に。
- 本文は明朝系10.5pt、見出しはゴシック系（やや大きめ）。英数字は半角、日本語は全角。
- 段落先頭は1字下げ。余計な改行・空行を入れない。長すぎる段落は意味で分ける。
- 「以下に」ではなく「次に」（直後を指すとき）。「以下に」は後続範囲全体を指すときだけ。
- 見出し直後にいきなり図表・コード・箇条書きを置かない。まず説明文を書く。
- **図の見出しは図の下**、**表の見出しは表の上**。図表は本文で必ず言及し、かつ図表だけでも意味が分かるようにする。
- 全角ダッシュ（——）は使わずカッコや読点に。丸数字（①等）は使わない。
- 見出しをページ末尾に孤立させない。

## コード系レポートのハイブリッド体裁（推奨）

正式さは保ちつつ、コード・表・図を読みやすくするため、プログラム課題では原則この体裁を採用する。課題指定があればそちらを優先する。

- 本文: 明朝系10.5pt。行間は1.15〜1.25倍を標準とし、1.5倍は課題指定がある場合だけ使う。
- 本文見出し: ゴシック系。章=13〜14pt太字、節=11.5〜12pt太字、項=10.5〜11pt太字。本文中の見出しを18pt/15pt級にしない。
- 表: キャプションは表の上。形式は `表 1: ...`、白背景、黒罫、ヘッダも原則白背景。本文で必ず参照する。
- 図: キャプションは図の下。形式は `図 1: ...`。図の大きさと線種を揃え、図1枚だけで意味が分かるようにする。
- フローチャート: 低解像度PNGを避け、Word内の罫線/テキスト、Office図形、またはベクター形式を優先する。ラスタ画像にする場合は高解像度・白背景・黒線・本文と同系統のフォントで統一する。
- 式: 必要なときだけ番号付きで `式 1: ...` とし、Word数式/OMMLを使う。コード中心レポートでは式を増やしすぎない。
- コードリスト: 白背景、黒い矩形枠、等幅フォント6.5〜7.2pt、画像化しない。ファイル単位の付録なら `A.1 file.c` のように実ファイル名と対応させる。
- コード抜粋: 本文中に置くときは「主要部」だけにし、全文は提出zipまたは付録に回す。キャプションは `リスト 1: ...`。

## 引用規則

- 出典は書籍など信頼できるもの。生成AIの出力や不確実なWebサイトを出典にしない。
- 本文に [1] のように番号を付け、引用箇所を明確にする。**番号は [1] から連番・欠番なし**。文献が1件でも [1]。引用していない文献は載せない。
- 書籍：著者・標題・発行所・発行年（可能ならページ）。論文：著者・標題・誌名・巻号頁・発行年。
- 他者と相談した場合はその旨を明記。剽窃をしない。

## 生成AIを利用した場合

- 課題が AI 記録の提出を求める場合、利用した生成AI・モデル/バージョン・プロンプト・応答の概要を記録する。
- 生成物は鵜呑みにせず、自分の環境でコンパイル・実行し、出力・数値を検証したうえで採用する旨を残す。
- 記録は事実のみ。やっていないことを「やった」、やったことを「やっていない」と書かない。
