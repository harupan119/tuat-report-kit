# TUAT レポート 提出前チェック

最終提出の前に実機で確認する。科目固有のチェックは科目メモ（`templates/course-memo.md` の形）にも書いておく。本文の機械検査は `scripts/report_gate.py`、PDF の検算は `tuat-report-pdf` の手順。

## 指示の監査

- 課題プロンプト・サンプル・採点基準・教員からの修正指示を読む。提出形式（DOCX/PDF/ZIP/LMSテキスト等）を確定する。
- 必須要件を抽出：フォント・サイズ・余白・ページ数・見出し・引用形式・付録要件・ファイル名・締切（表紙の要否と項目も確認し、要る場合は別途用意する）。
- 指示が衝突する場合は**新しく具体的な指示を優先**する。

## 内容チェック

- 目的・方法・結果・考察・結論が明確か。結果は事実、解釈は考察に分離されているか。
- すべての図表を本文で言及・説明しているか。図表は単体でも意味が分かるか。
- 教科書・規格・論文・API・製品仕様・Web 等からの主張に出典が付いているか。
- 実験/プログラムレポートに、環境・入力・計測法・反復回数/統計・再現性メモがあるか。
- 考察が「何が起きたか」だけでなく「なぜ起きたか」を説明しているか。
- 付録は本文から参照され、説明なく添付されていないか。

## 体裁チェック

- 課題指定のフォント・サイズ。未指定なら本文=明朝、見出し=ゴシック。誤った太字・斜体がないか。
- 表の背景は原則白・黒罫。コードリストは白背景・黒枠。数式は数式オブジェクト/高品質レンダリング。
- **図表・コード・数式の番号が連番**（重複・欠番なし）。図見出しは図の下、表見出しは表の上。
- 見出し直後に説明文なしで図表・コード・箇条書きを置いていないか。

## よくある落とし穴（共通）

- [ ] **式番号**の重複・欠番。PDFは `pdftotext -layout` で `式\d+` を抽出して連番確認。
- [ ] **参考文献番号**が [1] 始まり・欠番なし・全件本文参照。
- [ ] **図表番号**が連番で全て本文言及。
- [ ] 表どうしで**同条件の数値が矛盾しない**（同条件は同一計測値を共有）。
- [ ] **考察が最新データと一致**（データ差し替え後に旧考察が残っていないか）。
- [ ] PDFで**図・数式・コードが欠落していない**（`textutil` は画像が落ちるので最終PDFに使わない）。
- [ ] ファイル名が規約どおり（学籍番号・氏名などを含める指定なら、その値が正しいか）。

## PDF チェック

```bash
pdfinfo PDF              # ページ数・サイズ
pdftotext PDF -          # 参考文献・主要数値の存在確認
pdftotext -layout PDF -  # レイアウト保持での抽出
pdftoppm -png -r 90 PDF page        # ページ画像にして空白/図崩れ/はみ出しを目視
```

## ZIP チェック

提出アーカイブが要る場合：

- 含める：再現/確認に必要なソース・データ・図・スクリプト・依存リスト（requirements 等）・説明。
- 除外：仮想環境(`.venv/`)・ビルド成果物・バイナリ(`*.o`,`*.out`,`*.exe`,`*.dSYM`)・キャッシュ(`__pycache__/`)・`.DS_Store`・`Thumbs.db`・教員からの修正指示ファイル（明示要求がない限り）。
- `python -c "import zipfile;print('\n'.join(zipfile.ZipFile('X.zip').namelist()))"` で包含・除外を明示的に確認（macOS は `python3`）。
- 別フォルダに展開して turn-key で再現（`make`→実行）できるか確認。
